## Story

As a Hexalith module developer,
I want to extract the creation timestamp from a ULID string,
so that I can determine when an event or entity was created directly from its ID without querying additional metadata.

## Acceptance Criteria

1. **Given** a valid ULID string generated by `GenerateSortableUniqueStringId()`
   **When** a developer calls `ExtractTimestamp(string ulid)`
   **Then** it returns a `DateTimeOffset` representing the ULID's creation time
   **And** the returned `DateTimeOffset` represents UTC time (ULID timestamps are Unix epoch milliseconds)
   **And** the returned timestamp is within 1 millisecond of the actual generation time

2. **Given** a null, empty, or whitespace string
   **When** a developer calls `ExtractTimestamp()`
   **Then** an `ArgumentException` is thrown (per ADR-006)

3. **Given** an invalid ULID format string (e.g., "short", "THIS_IS_NOT_A_VALID_ULID!!")
   **When** a developer calls `ExtractTimestamp()`
   **Then** a `FormatException` is thrown with a descriptive message (per ADR-006)

4. **Given** all changes are complete
   **When** `dotnet build` and `dotnet test` are executed
   **Then** zero warnings, zero errors, and all existing + new tests pass

## Dev Notes

### Architecture Context

This story implements **Architecture step 10** from the 12-step test-gated implementation sequence. It adds timestamp extraction from ULID strings — a thin wrapper over ByteAether's `Parse` + `.Time` API.

**ADR-005 (No ByteAether in Public API):** Return `DateTimeOffset` only. ByteAether types are internal implementation details.

**ADR-006 (Exception-based Error Handling):** Use `ArgumentException.ThrowIfNullOrWhiteSpace()` for null/empty input. Wrap ByteAether parse failures in `FormatException` with descriptive message. Do NOT use `ValueOrError<T>` — invalid ULID is a programmer error.

**FR6 Coverage:** This story fully satisfies FR6 ("Developer can extract the creation timestamp from a ULID string as a `DateTimeOffset`").

### Verified ByteAether.Ulid v1.3.5 API

**CRITICAL: These are the exact API names verified from ByteAether.Ulid documentation — do NOT guess or invent alternatives.**

| API                    | Usage                                                                                    |
| ---------------------- | ---------------------------------------------------------------------------------------- |
| `BaUlid.Parse(string)` | Parse ULID from string. Throws on invalid format.                                        |
| `.Time`                | Instance property. Returns `DateTimeOffset` representing the ULID's timestamp component. |

The type alias `using BaUlid = ByteAether.Ulid.Ulid;` is already present in `UniqueIdHelper.cs` (added in Story 2.1).

### Exact Code Changes

**File: `src/libraries/Hexalith.Commons.UniqueIds/UniqueIdHelper.cs`**

Add ONE public method. **SA1201 alphabetical ordering:** `ExtractTimestamp` sorts BEFORE `GenerateDateTimeId`, so insert it as the FIRST public method.

```csharp
/// <summary>
/// Extracts the creation timestamp from a ULID string.
/// </summary>
/// <param name="ulid">A 26-character ULID string in Crockford Base32 format.</param>
/// <returns>A <see cref="DateTimeOffset"/> representing the ULID's creation time in UTC.</returns>
/// <exception cref="ArgumentException">Thrown when <paramref name="ulid"/> is null, empty, or whitespace.</exception>
/// <exception cref="FormatException">Thrown when <paramref name="ulid"/> is not a valid ULID string.</exception>
public static DateTimeOffset ExtractTimestamp(string ulid)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(ulid);
    try
    {
        return BaUlid.Parse(ulid).Time;
    }
    catch (Exception ex) when (ex is not ArgumentException)
    {
        throw new FormatException($"The value '{ulid}' is not a valid ULID string.", ex);
    }
}
```

**That's it — 1 method addition to the source file. No fields, no locks, no state.**

Notes:

- String interpolation in the `FormatException` message is acceptable — this is the error path, not the hot path
- The `when (ex is not ArgumentException)` guard ensures `ThrowIfNullOrWhiteSpace` exceptions pass through unchanged
- ULID operations are culture-invariant (Crockford Base32 is ASCII-only) — no `CultureInfo` needed

### Test Implementation Guidance

**File: `test/Hexalith.Commons.Tests/UniqueIds/UniqueHelperTest.cs`**

Add ~4 new test methods following existing patterns. All tests use `[Fact]` or `[Theory]` with Shouldly assertions.

**Valid timestamp extraction test:**

```csharp
/// <summary>
/// Tests that extracting a timestamp from a freshly generated ULID
/// returns a UTC time within 1 millisecond of the actual generation time.
/// </summary>
[Fact]
public void ExtractTimestampFromGeneratedUlidReturnsTimestampWithinOneMillisecond()
{
    DateTimeOffset before = DateTimeOffset.UtcNow;
    string ulid = UniqueIdHelper.GenerateSortableUniqueStringId();
    DateTimeOffset after = DateTimeOffset.UtcNow;

    DateTimeOffset timestamp = UniqueIdHelper.ExtractTimestamp(ulid);

    timestamp.ShouldBeGreaterThanOrEqualTo(before.AddMilliseconds(-1));
    timestamp.ShouldBeLessThanOrEqualTo(after.AddMilliseconds(1));
}
```

**UTC verification test:**

```csharp
/// <summary>
/// Tests that the timestamp extracted from a ULID is in UTC (offset is zero).
/// </summary>
[Fact]
public void ExtractTimestampFromUlidReturnsUtcTime()
{
    string ulid = UniqueIdHelper.GenerateSortableUniqueStringId();

    DateTimeOffset timestamp = UniqueIdHelper.ExtractTimestamp(ulid);

    timestamp.Offset.ShouldBe(TimeSpan.Zero);
}
```

**Null/empty/whitespace error test:**
